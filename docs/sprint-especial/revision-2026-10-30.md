## Aislamiento por base de datos

Los archivos locales `065`–`076` se renumeraron desde las versiones locales previas `060`–`071`, dejando intactos los archivos de main `059`–`064`; se añadió `077_backup_scheduler_schema_access.sql`. El runner completo se ejecutó sobre una base temporal restaurada y aplicó ambos nombres `059_*` y luego `060`–`077` sin colisión. El registro guarda el nombre completo de cada migración.

La base principal local y `BasePruebaTenants` no recibieron estas migraciones en esta revisión. El Compose normal mantiene el routing y la separación desactivados; para que altas nuevas se separen automáticamente deben estar aplicadas las migraciones, habilitado el routing/aislamiento y en ejecución el worker. El recorrido histórico de onboarding HTTP se probó con superusuario en la base sintética; el worker con una cuenta dedicada de privilegios mínimos y la comprobación de credenciales por tenant siguen pendientes. No se deben guardar contraseñas en los README; una guía debe listar usuarios/roles y apuntar a un archivo local protegido para secretos.

Los dos fixtures `TENANT_AUDIT_CHAIN_INVALID` quedan bloqueados por integridad: su cadena no verifica después de mutaciones fuera del flujo auditado. No se reescribieron. Para pruebas nuevas usar tenants sintéticos nuevos o pedir revisión de evidencia antes de cualquier reparación.
